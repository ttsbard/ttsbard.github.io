# Лендинг TTSBard на GitHub Pages: публикация, индексация и концепция

Примечание 2026-10-20: историческое исследование сохранено как основание.
Выбран отдельный репозиторий `ttsbard/ttsbard.github.io` и корневой адрес
`https://ttsbard.github.io/`; актуальное состояние — в [плане](roadmap.md).

Дата исследования: **2026-10-19**. Продуктовая база: TTSBard **1.6.0**,
commit `33140fd`, remote `git@github.com:alksef/TTSBard.git`.

**Статус:** исследование и предложение для обсуждения. Структура сайта,
адреса и способ публикации не являются утверждённым архитектурным решением.
Сайт в рамках исследования не создан и не опубликован.

## 1. Вывод

GitHub Pages подходит для бесплатного публичного лендинга TTSBard.
Покупать домен, арендовать сервер и настраивать сервер приложения не требуется.
Предлагаемый старт: адрес `https://alksef.github.io/TTSBard/`, статический
лендинг с русской и английской версиями, реальные скриншоты и ссылка на Releases.

Это разумная основа для поиска по названию TTSBard и конкретным сценариям.
Появление сайта в индексе и высокие позиции — разные результаты:
GitHub Pages обеспечивает публикацию, но не гарантирует ни индексацию,
ни позиции по общим запросам о TTS. Google прямо предупреждает, что выполнение
технических требований не гарантирует индексацию. [1, 7]

Главное сообщение лендинга: **быстро общаться голосом через ввод текста,
не теряя темп игры или трансляции**. Возможности приложения раскрывать через
пользовательские сценарии, а не переносить весь список настроек в первый экран.

## 2. Как работает GitHub Pages

Pages получает HTML, CSS, JavaScript и изображения из репозитория и публикует
их как статический сайт. Файлы можно размещать напрямую или предварительно
собирать генератором сайта. Серверный код Rust, Python или PHP на Pages
не запускается. Для информационного лендинга он и не нужен. [1]

На GitHub Free Pages доступен для публичных репозиториев. Условия приватных
репозиториев зависят от плана. Адрес на `github.io` предоставляется GitHub;
собственный домен необязателен. HTTPS поддерживается, для адреса `github.io`
включается автоматически. [1, 3]

### Варианты адреса

| Вариант | Пример для проекта | Что требуется |
|---|---|---|
| Сайт проекта | `https://alksef.github.io/TTSBard/` | Включить Pages у репозитория `alksef/TTSBard` |
| Сайт аккаунта | `https://alksef.github.io/` | Репозиторий с точным именем `alksef.github.io`; один такой сайт на аккаунт |
| Отдельный брендовый аккаунт/организация | Например, `https://ttsbard.github.io/` | Соответствующий доступный аккаунт/организация и репозиторий; доступность имени не проверялась |

Первый вариант использует уже существующие владельца и репозиторий.
Третий не нужен для первой версии: это дополнительное организационное решение.
Различия адресов и ограничения числа сайтов описаны GitHub. [1]

### Два способа публикации

**Из ветки.** В `Settings → Pages → Build and deployment` выбрать
`Deploy from a branch`, затем ветку и `/ (root)` либо `/docs`.
Произвольную папку вроде `/site` этим способом выбрать нельзя.
При обновлении выбранного источника GitHub публикует изменения. [2]

**Через GitHub Actions.** В `Settings → Pages` выбрать `GitHub Actions`.
Отдельный workflow забирает подготовленные файлы, при необходимости собирает
их, загружает Pages-артефакт и развёртывает сайт. Так можно публиковать только
содержимое `site/`, независимо от остальных файлов репозитория. [2]

### Предложение для TTSBard

Хранить исходники в отдельной папке `site/` текущего репозитория и публиковать
её отдельным Pages workflow. Это немного больше первоначальной настройки,
но не требует второго репозитория и позволяет явно ограничить опубликованные
файлы. Действующий `.github/workflows/build.yml` занимается сборкой приложения;
публикацию лендинга предлагается оформить отдельным workflow.

Альтернатива с минимальным количеством настроек — отдельный публичный репозиторий
сайта и публикация его корня из ветки. Это даст адрес по имени того репозитория;
для корня `alksef.github.io` потребуется одноимённый репозиторий аккаунта.

Существующий `docs/` содержит исследования и внутреннюю документацию разработки.
Публиковать его целиком только ради лендинга нецелесообразно. Эта оценка
относится к организации текущего репозитория, а не к ограничению Pages.

Для первой версии достаточно HTML и CSS, небольшого JavaScript для увеличения
изображений при необходимости. Vue/React, CMS и генератор документации не нужны.
Если позднее появится большой раздел инструкций, выбор генератора можно
пересмотреть. Это предложение, реализация ещё не согласована.

### Где будут загрузки

Кнопка скачивания ведёт на
`https://github.com/alksef/TTSBard/releases/latest`.
На Pages находятся описание и изображения; установщики и архивы остаются
в GitHub Releases. Поэтому новая версия программы не требует перекладывать
дистрибутив на сайт. Если показывать номер версии или прямую ссылку на файл,
нужно отдельно обеспечить их актуализацию.

Опубликованный Pages-сайт ограничен 1 GB; мягкий лимит трафика — 100 GB в месяц.
Небольшой лендинг с несколькими оптимизированными изображениями по проектной
оценке значительно ниже этих объёмов. Pages не предназначен для коммерческих
транзакций и коммерческого SaaS; рассматриваемый сценарий — информационный
сайт открытого desktop-приложения со ссылками на Releases. [4]

## 3. Что показывает пример TTS Voice Wizard

Проверены [главная](https://ttsvoicewizard.com/) и
[репозиторий](https://github.com/VRCWizard/TTS-Voice-Wizard).

У главной есть короткое позиционирование, кнопка загрузки, блоки возможностей
с изображениями и ссылки на начало работы. Отдельно доступны документация
и блог. То есть референс — простой вход в более широкий сайт, а не только
единственная страница. [5, 6]

Для TTSBard полезно взять ясную последовательность: назначение → скачивание →
возможности → инструкции. Не стоит переносить чужой акцент на распознавание
речи, перевод и VRChat: сильный исходный сценарий TTSBard — быстрый ввод текста
и отправка реплики в нужные направления.

По изученным страницам не устанавливались фактический хостинг
`ttsvoicewizard.com`, настройки Search Console, поисковый трафик или причины
ранжирования. Наличие собственного домена у референса не доказывает,
что домен нужен TTSBard для индексации.

## 4. Два языка и поисковая доступность

Предлагаемые URL:

```text
https://alksef.github.io/TTSBard/       — полный английский лендинг
https://alksef.github.io/TTSBard/ru/    — полный русский лендинг
```

Получаются две языковые версии одного одностраничного дизайна. Английский
в корне — предложение для международной аудитории; русский можно сделать
основным, сохранив тот же принцип отдельных URL. На каждой странице —
видимый переключатель `Русский / English` обычными ссылками.

Google рекомендует отдельные адреса для языковых версий и предупреждает
о проблемах автоматического перенаправления по предполагаемому языку.
Поэтому основной контент должен уже содержаться в HTML каждой версии;
языковой переключатель не должен только заменять текст по одному URL. [8]

Для каждой версии предусмотреть:

- полностью переведённый текст, заголовки, подписи, FAQ и метаданные;
- `lang="en"` / `lang="ru"` для корректной семантики и доступности;
- собственный canonical URL, чтобы обе версии сохраняли свои адреса;
- взаимные `hreflang="en"` и `hreflang="ru"`, включая ссылку на себя;
- при необходимости `x-default`, указывающий на корневую версию.

Связи `hreflang` должны быть взаимными, с полными URL. Google определяет язык
по содержимому, а `hreflang` помогает связать альтернативные версии. [9]

### Практический минимум для поиска

1. Обе страницы публично доступны и возвращают HTTP 200; нет `noindex`
   и блокирующего обход правила. На странице есть индексируемый текст. [7]
2. Различимые `title`, description, один ясный основной заголовок, тематические
   подзаголовки и обычные HTML-ссылки. Пример title:
   `TTSBard — text-to-speech for gaming and streaming on Windows`.
   Русский: `TTSBard — программа для общения голосом через текст`.
   Это редакционные предложения для реализации.
3. Скриншоты сопровождаются содержательными текстовыми подписями и alt.
   Назначение приложения должно быть понятно и без изображений.
4. Небольшой `sitemap.xml` с двумя языковыми URL. Для такого сайта карта
   не обязательна при нормальных ссылках, но полезна для подачи нового сайта
   поисковикам. Она не гарантирует индексацию. [10]
5. Добавить URL-prefix ресурс `https://alksef.github.io/TTSBard/`
   в Google Search Console; подтвердить права HTML-файлом или метатегом.
   DNS-подтверждение чужого домена `github.io` не требуется. Отправить sitemap
   и проверить обе страницы через URL Inspection. [7, 11]
6. Для русскоязычной аудитории добавить сайт в Яндекс Вебмастер,
   подтвердить права и передать sitemap средствами сервиса. [13]
7. Разместить ссылку на лендинг в README, поле Website/About репозитория
   и описаниях релизов. Это создаёт понятные входы на сайт из проекта.

**Особенность robots.txt у сайта проекта:** робот ищет файл в корне хоста —
`https://alksef.github.io/robots.txt`. Файл
`https://alksef.github.io/TTSBard/robots.txt` не управляет обходом проекта.
Если корнем хоста управляет сайт аккаунта, сначала проверить его правила.
Отдельный разрешающий robots.txt не обязателен; sitemap можно передать
через инструменты вебмастера. [12]

Цели поиска лучше разделить:

| Цель | Оценка |
|---|---|
| Находить официальный сайт по `TTSBard` / `TTS Bard` | Разумная первая цель после появления страниц в индексе |
| Находить по конкретному сценарию: TTS для игр, OBS, Twitch, локальный Piper | Возможное развитие; на странице нужны содержательные описания этих сценариев |
| Конкурировать по общим `TTS`, `text to speech`, `синтез речи` | Нельзя обещать на основании одного лендинга; потребуется отдельная оценка спроса и результатов |

Это качественная оценка, исследование частотности и мониторинг позиций
не выполнялись. Контроль результата — статус страниц, показы, запросы и клики
в инструментах вебмастера. Срок попадания в индекс заранее не обещается.

## 5. Предлагаемая концепция лендинга

### Первый экран

Верхняя строка: логотип и TTSBard, ссылки-якоря «Возможности», «Скриншоты»,
«Как начать», ссылка GitHub, переключатель языка.

Основной текст:

> **TTSBard — быстрый голос для общения и стриминга**
>
> Набирайте текст — TTSBard произнесёт его в игре или голосовом чате.
> Вызывайте редактор горячей клавишей, показывайте реплики в OBS
> и отправляйте их в Twitch или VRChat.

Кнопки: **«Скачать для Windows»** и «Первый запуск».
Под ними: `Windows 10/11 · Открытый исходный код · Русский / English`.
Рядом — крупный скриншот редактора с короткой понятной репликой.

Английский черновик:

> **TTSBard — a quick voice for gaming and streaming**
>
> Type a message and let TTSBard speak it in your game or voice chat.
> Open the editor with a hotkey, display your messages in OBS,
> and send them to Twitch or VRChat.

Текст основан на [обзоре продукта](https://github.com/ttsbard/TTSBard/blob/master/docs/ru/ttsbard-overview.md), который можно
использовать как текстовую основу для сокращения PDF-презентации.
PDF-файлы в этом исследовании отдельно не извлекались и визуально не проверялись.
Формулировки требуют редакционного согласования перед публикацией.

### Порядок секций

| Секция | Что показать | Зачем посетителю |
|---|---|---|
| Быстрый сценарий | Вызвать редактор → написать → озвучить → вернуться к игре; возврат фокуса настраивается | Сразу понять повседневную пользу |
| 4–6 ключевых возможностей | Быстрый редактор, локальные и облачные голоса, аудиокэш, два аудиовыхода, интеграции, саундпад | Увидеть причины попробовать |
| Программа в работе | Основной редактор, компактный вид/«Моно», саундпад, пример вывода текста в OBS | Представить реальные окна и результат |
| Голоса и интеграции | Silero Bot, Piper, OpenAI, ElevenLabs, Fish Audio; OBS, Twitch, VRChat, VTube Studio, LunaTranslator | Проверить нужную связку |
| Как начать | Скачать → выбрать и настроить голос → выбрать аудиовыход → отправить первую фразу | Снизить сложность первого запуска |
| FAQ | Бесплатность, интернет, голосовой чат, Windows, установка моделей и внешних сервисов | Ответить на вопросы до скачивания |
| Нижний блок | Повтор кнопки загрузки, документация, Issues, лицензия GPL-3.0-only | Дать понятное следующее действие |

OCR, RUAccent и входящий сервер можно упомянуть коротким дополнительным
абзацем или в раскрытии возможностей. Начальную страницу не стоит превращать
в полный каталог настроек. Основной приоритет — общение через ввод текста;
озвучивание игр и внешнего текста — дополнительный сценарий.

### Какие скриншоты подготовить

Предлагаются четыре изображения, считая первый экран:

1. **Основной редактор:** читаемый текст, вкладки и направления отправки.
2. **Компактный редактор / «Моно»:** демонстрация небольшого окна рядом
   с игровым или рабочим контекстом.
3. **Саундпад:** заполненная сетка с понятными примерами звуковых реакций.
4. **Результат в OBS:** реплика, отображаемая на демонстрационной сцене.

У каждого изображения — короткая подпись с конкретным действием или пользой.
Лучше обычная сетка или последовательность блоков с увеличением по клику:
все изображения доступны сразу, без ожидания автоматической карусели.
На телефоне они выстраиваются в одну колонку.

Снимать актуальную версию в едином масштабе и выбранной теме, с демонстрационными
текстами. Для каждой языковой версии предпочтительны снимки соответствующего
языка интерфейса. Удалить из кадра API-ключи, токены, персональные сообщения
и идентификаторы аккаунтов. Макеты будущих функций не выдавать за реальные окна.
В проверенном tracked-наборе изображений найдены иконки приложения;
готовый комплект скриншотов для лендинга не установлен.

Поисковый текст нельзя заменить надписями внутри картинок. Основной текст
оставить в HTML; изображения оптимизировать, задать размеры и отложенную
загрузку для секций ниже первого экрана. Визуальный характер — близкий
к приложению, с крупными читаемыми окнами и одним основным акцентом скачивания.
Дизайн лендинга пока предлагается, а не объявляется новым стандартом UI.

### Точность обещаний

Сверка с текущими README и обзором продукта:

- Бесплатное открытое приложение не означает бесплатность всех облачных голосов:
  внешние сервисы могут требовать аккаунт, ключ и оплату по своим условиям.
- Работа без интернета относится к Piper после установки модели;
  её нельзя распространять на все провайдеры и интеграции.
- Для передачи звука в Discord или игру нужен настроенный виртуальный
  аудиокабель. Само наличие приложения его не заменяет.
- Аудиокэш ускоряет повторные фразы с теми же настройками;
  обещание мгновенного синтеза любого нового текста не подтверждено.
- VTube Studio получает состояние набора; полноценную артикуляцию заявлять нельзя.
- Текущая заявленная платформа — Windows 10/11; Linux пока исследуется.
- AI-коррекция обозначена в README как экспериментальная; её не следует
  делать центральным обещанием лендинга.

## 6. Предлагаемый объём первой реализации

После согласования концепции:

1. Уточнить тексты RU/EN и подготовить четыре актуальных скриншота.
2. Сделать адаптивные статические страницы с одинаковой структурой,
   доступной навигацией и ссылками на существующие инструкции.
3. Добавить метаданные, canonical, hreflang, sitemap и превью ссылки
   для социальных сетей. Превью нужно для внешнего вида ссылки,
   оно не является гарантией поисковых позиций.
4. Подготовить отдельный Pages workflow, публикующий только сайт;
   фильтровать его запуск изменениями сайта и самого workflow.
5. До публикации проверить обе локали, мобильную ширину, клавиатуру,
   читаемость картинок, скачивание и открытие инструкций.
6. После публикации проверить HTTPS, HTTP 200, прямое открытие `/ru/`,
   пути изображений под `/TTSBard/`, отсутствие `noindex` и доступность sitemap.
7. Подтвердить сайт в инструментах Google/Яндекса и проверить обнаружение
   обеих языковых версий. Успешный deploy сам по себе не подтверждает индексацию.

Ориентировочно **1–2 рабочих дня** на первый вариант при готовых текстах
и скриншотах, включая настройку Pages и базовую проверку. Это оценка объёма,
а не обязательство; согласование оформления и ожидание индексации сюда не входят.

Для принятия решения остаются три предпочтения: размещение в текущем
репозитории через Actions либо отдельном репозитории; основной язык в корне;
набор и оформление скриншотов. Рекомендуемый старт — текущий репозиторий,
английская версия в корне и русский `/ru/`, четыре скриншота.
